# Agent 基础

## 什么是 Agent

Agent = LLM + 记忆 + 工具 + 规划。

它是一个自主的智能程序：能感知环境（读取输入）、决策（用 LLM 思考）、行动（调用工具做事）、观察结果、再决策。这个循环是 Agent 的心跳。

## Agent 的记忆机制

LLM 本身是无状态的 —— 每次 API 调用都是独立的。它不会"记得"你上一次说了什么。

为了让 Agent 表现得像"有记忆"，我们用 messages 数组累积对话历史。每一轮把用户消息和 LLM 回复都追加进去，下一次调用时把整个历史一起发过去。LLM 从中"读出"上下文，看起来就像它记住了一切。

这种做法有两个代价：

1. **上下文长度限制**：模型能处理的 token 有上限（例如 32k、200k），塞得太长会报错或性能下降。
2. **token 成本线性增长**：每一轮输入的 token 数都在增加，跟对话次数成正比。

## 短期记忆 vs 长期记忆

- **短期**：当前对话的 messages 数组，几百到几万 token
- **长期**：向量数据库里存的知识片段、结构化数据库、外部记忆存储

Agent 在需要时从长期记忆检索出相关片段，塞进当前对话作为参考。这是 RAG 的核心思想。

## Tool Use（工具调用）

给 LLM 提供一个工具列表（schema），当它判断需要用某个工具时，会返回一个特殊的响应结构 tool_calls，包含工具名和参数。你的代码执行完，把结果作为 role="tool" 的消息传回去，LLM 再基于结果继续。

一次用户提问可能触发多轮 LLM 调用和工具执行，直到 LLM 认为任务完成为止。所以 Agent 的核心是一个 while 循环。
